# 프로젝트 구조와 실행 방식

기존 개발 준비 계획과 ADR의 2일 MVP를 기준으로 한다. 현재는 프론트 목업과 폴더·빈 파일 뼈대 단계이며, 아래 백엔드 실행 방식은 구현할 계약이다.

## 모듈 경계

| 경로 | 역할 |
| --- | --- |
| `app/main.py` | FastAPI 진입점. lifespan에서 MCP 연결을 관리하고, 데모에서는 Vue 빌드 결과를 서빙 |
| `app/api/routes/` | `/api` REST 및 SSE |
| `app/core/config.py` | 환경변수 설정. LLM 설정과 임베딩 설정을 분리 |
| `app/schemas/` | API, AI 상태, SSE, 평가가 공유하는 Pydantic 모델 |
| `app/ai/llm.py` | LLM 공통 게이트웨이. 공급자 전환, 출력 검증, 재시도, 사용량 기록 |
| `app/ai/embeddings.py` | 규정·질의 공통 임베딩 호출. LLM 공급자 전환과 독립 |
| `app/ai/workflow.py` | 단계 순서, 병렬 분기, 재시도 및 타임아웃 |
| `app/ai/state.py` | 실행 상태, 규정·프롬프트·모델 버전, 증적 정보 |
| `app/ai/stages/` | 추출, 검색, 공시 대조, 판정, 검증 단계 |
| `app/ai/prompts/` | 단계별 프롬프트 파일 |
| `app/kb/` | 로컬 규정 벡터 검색과 필수사항 체크리스트 |
| `app/integrations/mcp/manager.py` | stdio 자식 프로세스, 세션 유지·종료·재기동 |
| `app/services/` | 검토 실행과 저장 조율 |
| `app/db/` | DB 연결, 모델, 저장소 |
| `mcp_servers/korean_law/` | 법제처 원천 조문 재조회. 로컬 벡터 검색과 분리 |
| `mcp_servers/fin_disclosure/` | 외부 공시 금리 조회 |
| `mcp_servers/common/` | 프로세스 내부 TTL 캐시 등 공통 유틸리티 |
| `ingest/` | 앱 실행과 독립된 규정 수집·파싱·청킹·임베딩·적재 |
| `data/regulations/raw/` | 수집한 규정 원문 |
| `data/regulations/processed/` | 정규화한 규정 청크 |
| `samples/` | 공공 API 응답 샘플. 키·개인정보 제외 |
| `evaluations/` | 데이터셋, 구성별 실행, 지표, 결과 |
| `migrations/` | DB 스키마 변경 |
| `scripts/` | 적재 외 개발·운영 보조 스크립트 |
| `docker/` | 추후 API 이미지 빌드 관련 파일. 별도 프론트 서버·Nginx 없음 |
| `web/` | Vue 3 + Vite 단일 페이지 |

개발 준비 계획의 `graph/`, `llm/gateway.py`, `mcp_client/`, `eval/`은 각각 현재 구조의 `app/ai/`, `app/ai/llm.py`, `app/integrations/mcp/`, `evaluations/`에 대응한다.

## 개발

- PostgreSQL + pgvector를 Docker Compose로 실행한다.
- FastAPI는 로컬 8000 포트에서 실행한다.
- Vite는 로컬 5173 포트에서 실행하고 `/api` 요청을 FastAPI로 프록시한다.
- 현재 목업은 API 호출이 없으며, 프록시와 FastAPI 실행 코드는 아직 구현하지 않았다.

## 데모

1. `web/`에서 `npm run build`로 `web/dist/`를 생성한다.
2. FastAPI가 `/api` 경로를 등록한 후 `web/dist/`를 루트 경로에서 서빙한다. API 경로가 정적 파일 처리에 가려지지 않게 한다.
3. 브라우저는 FastAPI 주소 하나로 화면과 API에 접근한다. Vite나 Nginx를 별도로 실행하지 않는다.
4. 컨테이너로 실행할 때는 Node 빌드 단계에서 생성한 프론트 결과물을 API 런타임 이미지에 복사한다. 빌드 파일 경로는 `app/main.py` 위치를 기준으로 해석해 실행 디렉터리에 의존하지 않게 한다.

MCP 서버 2개는 API 프로세스가 lifespan에서 stdio 자식 프로세스로 시작하고 종료한다. 별도 MCP 컨테이너는 두지 않는다. DB는 별도 컨테이너를 사용한다.

실제 정적 파일 서빙, lifespan, Compose 및 Dockerfile 구현은 후속 개발에서 추가한다. 프론트 빌드가 없으면 API 개발은 가능하도록 하고, 데모 실행 시에는 빌드 여부를 확인한다.
