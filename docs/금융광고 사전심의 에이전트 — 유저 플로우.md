# 금융광고 사전심의 에이전트 — 유저 플로우

Oct 20, 2026 · @seungeun moon

## 개요

**사용자:** 은행 준법감시 부서의 광고 심의 담당자 1명 ([MVP 기획서](https://claude.ai/code/artifact/8fa7d311-4a40-471b-adf1-13d12e94494b))

**목표:** 올라온 예·적금 광고 문안을 넣으면, 1분 안에 위반 소지 문구와 근거 조문, 수정안이 담긴 리포트를 받아 심의 의견을 빠르게 확정합니다.

**시작과 끝:** 화면 1개에서 시작하고 끝납니다. 광고 문안을 넣는 것에서 시작해, 판정별로 동의·기각을 마치거나 새 검토를 시작하면 끝납니다.

**설계 원칙:**

- **기다리는 동안 무엇이 진행 중인지 보여줍니다.** 검토는 최대 60초가 걸리므로, 단계 진행과 판정 도착을 실시간으로 표시합니다 (ADR-005).
- **판정은 도착하는 대로 하나씩 보여줍니다.** 모든 판정이 끝날 때까지 빈 화면으로 두지 않습니다.
- **근거를 확인하지 못한 판정은 숨기지 않고 구분해서 보여줍니다.** 검증에 실패한 판정은 "사람 확인 필요"로 표시해, 담당자가 직접 판단하도록 넘깁니다.
- **실패해도 그때까지의 결과는 남깁니다.** 한 단계가 실패해도 이미 받은 판정은 화면에 유지합니다.

## 메인 플로우

&#91;embedded content: 메인 플로우 · 입력 4단계, 진행·판정, 확정\]

윗줄은 사용자가 직접 하는 입력, 가운랫줄은 서버가 SSE로 보내는 진행 상황, 아랫줄은 담당자가 결과를 확정하는 단계입니다. 판정은 도착하는 대로 인용 검증 결과에 따라 두 종류의 카드로 나뉩니다.

## 단계별 상세

| 단계 | 사용자 행동 | 화면 반응 | API·SSE | 컴포넌트 |
| --- | --- | --- | --- | --- |
| 1. 화면 진입 | 페이지를 연다 | 빈 입력 폼, 검토 시작 버튼 비활성 | — | `App.vue` |
| 2. 문안 입력 | 광고 문안을 붙여넣는다 | 글자 수 표시. 문안이 있으면 검토 시작 버튼 활성 | — | `AdInput` |
| 3. 상품 선택 | 은행명·상품명으로 검색해 공시 상품을 고르거나 건너뛴다 | 후보 목록 표시, 선택한 상품의 기본·최고 금리 미리보기 | `GET /api/products` | `ProductPicker` |
| 4. 검토 시작 | 검토 시작 버튼을 누른다 | 입력 영역 잠금, 진행 표시 영역 열림 | `POST /api/runs` → `run_id` 받은 뒤 `GET /api/runs/{id}/events` 구독 | `useRunEvents` |
| 5. 단계 진행 | 기다린다 | 추출 → 검색 → 대조 → 판정 → 검증 순서로 현재 단계 강조 | `stage` 이벤트 | `StageProgress` |
| 6. 판정 수신 | 도착한 판정을 먼저 읽기 시작한다 | 판정 카드가 하나씩 추가되고, 원문의 해당 문구에 하이라이트 | `verdict` 이벤트 | `VerdictList` |
| 7. 리포트 완료 | 전체 리포트를 확인한다 | 진행 표시가 완료로 바뀌고, 위반 소지·주의·사람 확인 필요 개수 요약 표시 | `done` 이벤트 → `GET /api/runs/{id}` | `VerdictList` |
| 8. 동의·기각 | 판정마다 동의하거나 사유를 적고 기각한다 | 카드에 처리 상태 표시 | `POST /api/runs/{id}/verdicts/{claim_id}/feedback` | `VerdictList` |
| 9. 새 검토 | 새 검토 버튼을 누른다 | 입력 폼 초기화, 이전 결과 지움 | — | `App.vue` |

8단계 동의·기각은 시간이 남으면 구현합니다 ([MVP 기획서](https://claude.ai/code/artifact/8fa7d311-4a40-471b-adf1-13d12e94494b)). 구현하지 않더라도 판정 카드의 자리는 처음부터 잡아 둡니다.

## 화면 상태

화면은 6개 상태 중 하나입니다. `useRunEvents`가 상태 하나를 들고 있고, 모든 컴포넌트는 이 상태만 보고 그립니다.

| 상태 | 들어오는 조건 | 화면에 보이는 것 | 사용자가 할 수 있는 것 |
| --- | --- | --- | --- |
| `idle` | 화면 진입, 새 검토 | 빈 입력 폼 | 문안 입력, 상품 선택 |
| `ready` | 문안이 1자 이상 | 입력 폼, 검토 시작 버튼 활성 | 검토 시작 |
| `running` | `POST /api/runs` 성공 | 입력 잠금, 단계 진행, 도착한 판정 카드 | 도착한 판정 읽기 |
| `done` | `done` 이벤트 수신 | 전체 리포트, 개수 요약 | 동의·기각, 새 검토 |
| `partial` | `error` 이벤트 수신 후 `done` | 받은 판정 카드 + 실패한 단계 표시 | 받은 판정 읽기, 다시 시도, 새 검토 |
| `failed` | 검토 생성 실패 또는 판정을 하나도 받지 못함 | 오류 메시지 | 다시 시도 |

**`partial`을 따로 둔 이유:** 공시 API가 응답하지 않아도 표현 위반(단정·보장 표현)은 판정할 수 있습니다. 한 단계가 실패했다고 전체를 실패로 처리하면, 이미 받은 유효한 판정까지 버리게 됩니다.

## 예외와 경계 흐름

| 상황 | 화면 처리 | 서버 처리 |
| --- | --- | --- |
| 상품을 선택하지 않음 | 리포트 상단에 "공시 대조 미수행" 표시. 금리 관련 판정은 나오지 않음 | 대조 단계를 건너뜀 |
| 상품 검색 결과 없음 | "공시 상품을 찾지 못했습니다" 안내와 건너뛰기 버튼 | — |
| 광고가 아닌 문서 | 리포트 상단에 "광고 해당 여부 확인 필요"와 판단 이유 표시 | 추출 단계에서 광고 해당성을 함께 판단 |
| 위반 소지 문구가 없음 | "위반 소지 문구를 찾지 못했습니다"와 검토한 조문 수 표시 | `done` 이벤트에 판정 0건 |
| 인용 검증 실패 | 해당 판정을 "사람 확인 필요" 카드로 표시. 숨기지 않음 | 1회 재검색 후에도 실패하면 강등 |
| 공시 API 응답 없음 | 진행 표시의 대조 단계에 실패 아이콘, 나머지 판정은 계속 표시 | `error` 이벤트 후 다음 단계 진행 |
| 법제처 API 응답 없음 | 해당 판정을 "근거 확인 실패"로 표시 | 검증 단계 강등 |
| SSE 연결 끊김 | "다시 연결하는 중" 표시. 받은 판정은 유지 | 브라우저가 `Last-Event-ID`로 재연결, 서버는 그 뒤 이벤트부터 재전송 |
| 60초 초과 | "시간이 오래 걸리고 있습니다" 안내, 진행 표시는 유지 | 단계별 타임아웃에 따라 강등하고 `done` 전송 |
| 검토 중 페이지 새로고침 | `run_id`가 남아 있으면 같은 검토를 다시 구독 | `run_event` 테이블에서 이벤트 재전송 |

새로고침 복구를 위해 `run_id`는 브라우저 `sessionStorage`에 저장합니다. 저장소를 쓸 수 없는 환경에서는 복구 없이 새 검토로 시작합니다.

## 판정 카드 구성

판정 카드는 담당자가 "이 판정을 믿어도 되는가"를 카드 하나 안에서 판단할 수 있게 구성합니다. 위에서 아래로 읽는 순서대로 배치합니다.

| 순서 | 항목 | 예시 | 데이터 출처 |
| --- | --- | --- | --- |
| 1 | 등급 | 위반 소지 / 주의 / 사람 확인 필요 | `Verdict.severity` |
| 2 | 문제 문구 | "최고 연 4.5%" (원문 하이라이트와 연결) | `Claim.quote`, `span` |
| 3 | 위반 유형 | 공시 사실 불일치 | `Verdict.code` |
| 4 | 판단 이유 | 광고 금리 4.5%, 공시 최고 금리 3.8% (공시 기준월 함께 표시) | 판정 근거, 공시 대조 결과 |
| 5 | 근거 조문 | 조문 번호와 원문, 시행일 | `article_id`로 조회한 청크 |
| 6 | 검증 상태 | 원천 재조회 완료 (조회 시각) / 근거 확인 실패 | 검증 결과 |
| 7 | 수정안 | "최고 연 3.8% (우대조건 충족 시)" | `Verdict.fix` |
| 8 | 처리 | 동의 / 기각 + 사유 | 담당자 입력 |

**사람 확인 카드**는 같은 구조이되, 5번 근거 조문 자리에 "근거를 확인하지 못했습니다"와 실패 이유를 보여주고, 7번 수정안은 표시하지 않습니다. 근거 없는 수정안이 그대로 쓰이는 일을 막기 위해서입니다.

카드 상단에는 항상 "AI 1차 의견" 표시를 둡니다. 최종 판단은 담당자의 몫이라는 점을 화면에서 분명히 합니다.

## 범위 밖

- 로그인과 사용자 구분 (담당자 1명 가정)
- 과거 검토 이력 목록과 검색
- 여러 광고를 한 번에 올리는 일괄 검토
- PDF, 이미지, 영상 광고 입력
- 심의 의견서 파일 내보내기
- 현업 직원이 직접 쓰는 화면

이 기능들은 [MVP 기획서](https://claude.ai/code/artifact/8fa7d311-4a40-471b-adf1-13d12e94494b)의 "뺀다" 목록과 같습니다. 추가할 때는 ADR-012의 재검토 조건(화면이 여러 개가 되면 라우터와 상태 관리 도입)을 먼저 봅니다.
