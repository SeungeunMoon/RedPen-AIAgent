# 최신 참조 구조 조사 — 법률·금융 에이전트

Oct 20, 2026 · @seungeun moon

## 결론

아키텍처 문서의 참조 패턴은 2024년 12월에 나온 Anthropic의 [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)를 기반으로 합니다. 이후 2025\~2026년에 나온 일반 에이전트, 법률, 금융 분야의 자료를 조사했습니다.

**지금 구조를 바꿀 근거는 없습니다.** 오히려 고정 워크플로, 검증 에이전트 분리, 읽기 전용 도구, 증적 저장 같은 설계 선택을 뒷받침하는 더 최신 근거가 나왔습니다. 다만 세 가지는 보강해야 합니다.

1. **검증 에이전트에 "근거 부적합(misgrounded)" 검사를 추가합니다.** 조문이 실재하고 문언이 일치해도, 그 조문이 판정을 실제로 뒷받침하지 않을 수 있습니다.
2. **도구 설계에 네임스페이스와 짧은 응답 원칙을 추가합니다.**
3. **상용 고려사항에 FINOS AIGF와 금융위 AI 가이드라인 매핑을 추가합니다.**

## 일반 에이전트 구조 (2025\~2026)

### Anthropic — How we built our multi-agent research system (2025.6)

[원문](https://www.anthropic.com/engineering/multi-agent-research-system). 리드 에이전트가 전체를 조율하고, 병렬로 동작하는 서브에이전트에 작업을 위임하는 오케스트레이터-워커 구조입니다.

| 글의 내용 | 이 프로젝트에 주는 의미 |
| --- | --- |
| 조사가 끝나면 결과를 별도의 CitationAgent에 넘겨 인용 위치를 찾고, 모든 주장이 출처에 귀속되게 함 | 검증 에이전트를 따로 둔 설계의 직접적인 선례 |
| 모든 에이전트가 같은 맥락을 공유해야 하거나 의존성이 많은 작업은 아직 멀티 에이전트에 잘 맞지 않음 | 동적 리드 에이전트 대신 고정 워크플로를 쓴 ADR-001의 근거 |
| 멀티 에이전트는 일반 채팅보다 약 15배 많은 토큰을 씀 | 역할 분리는 하되 자율 협업은 피한 이유 |
| 실제 사용을 대표하는 약 20개 질의로 평가를 바로 시작함 | 골든셋 40건으로 시작해도 충분하다는 근거 |
| LLM 심판 루브릭에 사실 정확도와 인용 정확도를 포함 | 근거 조문 정확도 지표의 근거 |
| 오류가 나면 처음부터 다시 하지 않고 중단 지점부터 재개하도록 체크포인트를 둠 | 상태 객체를 단계마다 저장하는 설계와 같은 방향 |

### Anthropic — Writing effective tools for agents (2025.9)

[원문](https://www.anthropic.com/engineering/writing-tools-for-agents). 도구는 다른 개발자용 API처럼 쓰지 말고 에이전트를 위해 설계해야 한다는 글입니다. 원칙은 세 가지입니다.

- 모든 API 엔드포인트를 그대로 감싸지 말고 필요한 도구만 고른다.
- 관련 도구를 명확한 네임스페이스로 묶어 에이전트의 혼동을 줄인다.
- 토큰은 아끼면서 신호가 높은 정보를 돌려준다.

같은 팀의 연구 시스템 글에서는, 도구 테스트 에이전트가 MCP 도구를 여러 번 써보고 설명을 다시 쓰게 했더니 이후 작업 완료 시간이 40% 줄었다고 합니다. 도구 설명 자체를 평가하고 고칠 대상으로 봐야 한다는 뜻입니다.

### 반론 — Cognition, Don't Build Multi-Agents

[요약 출처](https://vladg.bearblog.dev/the-best-articles-on-building-agents/). 멀티 에이전트 구조는 아직 깨지기 쉽고 과하게 복잡하므로, 도구와 메모리를 갖춘 단일 에이전트를 권한다는 주장입니다. 이 프로젝트는 이 반론을 받아들여 에이전트끼리 자율적으로 협업하지 않고, 고정 워크플로 안에서 역할만 나눴습니다. 면접에서 "왜 멀티 에이전트냐"는 질문에 대한 답이 됩니다.

## 법률 도메인

### Harvey — Agent Builder (2026.3)

[원문](https://harvey.ai/blog/introducing-agent-builder). Harvey가 든 예시가 이 프로젝트와 거의 같습니다. 사내 법무팀이 Workflow 에이전트로 기존 사내 정책을 검색해 최신 규제와 맞지 않는 문구를 표시하고, 에이전트는 접근이 맞는지와 문서를 직접 고쳐도 되는지를 사용자에게 확인받습니다.

- **이 프로젝트에 주는 의미:** "규정 대조 → 플래그 → 사람 확인" 구조가 업계 선도 제품의 패턴과 같습니다. 사람 확인 단계를 그래프의 필수 노드로 둔 설계의 근거입니다.
- 2026년 5월에는 500개가 넘는 기본 에이전트를 공개했는데, 이 에이전트들은 정확도와 관련성 평가 벤치마크로 검증된 것이라고 밝혔습니다 ([Lawyers Weekly](https://www.lawyersweekly.com.au/biglaw/44287-harvey-rolls-out-500-legal-ai-agents)). 평가셋 없이 에이전트를 내놓지 않는다는 원칙의 근거입니다.

### Stanford RegLab·HAI — 법률 RAG 환각 연구 (2024)

[원문](https://hai.stanford.edu/news/ai-trial-legal-models-hallucinate-1-out-6-queries). 이 연구에서 **보강할 점**이 나옵니다.

- RAG 기반 상용 법률 리서치 도구도 Lexis+ AI와 Ask Practical Law AI는 17% 이상, Westlaw AI-Assisted Research는 34% 이상 잘못된 정보를 냈습니다.
- 연구는 오류를 두 종류로 나눕니다. 법을 틀리게 설명하는 **incorrect**, 그리고 법은 맞게 설명했지만 그 주장을 뒷받침하지 않는 출처를 인용한 **misgrounded**입니다 ([Business Law Today](https://businesslawtoday.org/?p=28988)).
- 인용이 실재한다는 좁은 의미에서 "환각이 없다"고 해도 그것만으로는 충분하지 않다는 점을 강조합니다.
- 이후 판례가 뒤집혔는지 같은 인용의 맥락도 함께 봐야 한다는 지적도 나왔습니다 ([Bloomberg Tax](https://news.bloombergtax.com/new-york-brief/ai-accuracy-in-legal-research-remains-in-check-your-work-phase)).

**이 프로젝트에 주는 의미:** 지금 검증 에이전트는 "조문이 실재하는가"와 "문언이 일치하는가"를 봅니다. 여기에 \*\*"그 조문이 이 위반 판정을 실제로 뒷받침하는가"\*\*를 별도 검사 항목과 지표로 추가해야 합니다. 판례가 뒤집히는 문제는 이 프로젝트에서는 규정 개정에 해당하며, 시행일 버전 관리와 원천 재조회로 이미 대응하고 있습니다.

## 금융 도메인

### FINOS — AI Governance Framework v2.0 (2025.11)

[원문](https://www.finos.org/blog/finos-ai-governance-framework-v2.0-addressing-agentic-ai-risks-in-a-rapidly-evolving-landscape). 금융권이 함께 만드는 오픈소스 AI 거버넌스 표준입니다. 이번 버전에 에이전트 AI 전용 위험 카탈로그가 추가됐고, OWASP, MITRE, EU AI Act 등 기존 프레임워크 7개와 상호 참조됩니다.

통제 항목 중 4개가 이 프로젝트의 설계와 거의 1:1로 맞습니다 ([FINOS의 FSB 제출 의견](https://www.fsb.org/uploads/FINOS.pdf)).

| FINOS 통제 | 이 프로젝트의 설계 |
| --- | --- |
| MI-13 인용과 출처 추적 | 판정마다 근거 조문을 붙이고 검증 에이전트가 원천을 재조회 |
| MI-18 에이전트 권한 최소화 | LLM에는 읽기 전용 도구만 노출, 쓰기는 오케스트레이터 전용 |
| MI-20 MCP 서버 보안 거버넌스 | MCP 서버를 신뢰 경계별로 분리하고 서버에서 감사 로그를 남김 |
| MI-21 에이전트 결정 감사 | 실행 상태 객체 전체를 증적으로 저장 |

**이 프로젝트에 주는 의미:** "금융권 표준 통제에 맞춰 설계했다"고 매핑 표로 보여줄 수 있습니다. 금융 IT 직무 면접에서 가장 설득력 있는 근거 중 하나입니다.

### 금융위원회 — 「금융분야 인공지능 가이드라인」 개정 (2026.6.22 시행)

[원문](https://fsc.go.kr/po010101/87142). 국내 기준입니다.

- 업종이나 업무와 관계없이 AI를 활용하는 모든 금융회사가 지켜야 할 자율규제로, AI 활용 7대 원칙을 제시합니다.
- 핀테크 같은 비금융회사도 AI 결과가 금융거래 제공에 영향을 주면 적용 대상입니다.
- 시행일에 맞춰 금감원의 「금융분야 AI 위험관리프레임워크」와 금융보안원의 「금융분야 인공지능 보안 실무 안내서」가 함께 배포됩니다 ([노컷뉴스](https://www.nocutnews.co.kr/news/6534884)).
- AI 에이전트 테스트를 위한 시범사업 운영방안도 하반기 과제로 검토됩니다 ([뉴데일리](https://biz.newdaily.co.kr/site/data/html/2026/06/18/2026061800173.amp.html)).

**이 프로젝트에 주는 의미:** 7대 원칙의 세부 내용은 원문을 확인한 뒤, FINOS와 같은 방식으로 설계 요소에 매핑합니다. 국내 금융사를 대상으로 한다면 FINOS보다 이 가이드라인이 1순위 기준입니다.
